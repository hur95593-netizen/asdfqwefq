# 架构、标准工作流与技术实现

## 分层架构

| 层 | 输入 → 输出 | 关键职责 |
|---|---|---|
| 发现层 | 目录 → inventory.json | 文件角色、入口候选、说明候选、mock 候选、hash、跳过项；不以扩展名直接认定业务范围 |
| 取证层 | 文件/运行页面 → evidence + 分析片段 | 源码行、可观测行为、文档原文、状态转换、原始数据备份 |
| 归一层 | 片段 → audit.json | 入口与页面分离、同名模块消歧、说明条款逐项归档、稳定 ID、冲突与范围裁决 |
| 生成层 | included 需求 → requirements.md + mock-data.md | 用户行为、规则、边界、验收；过滤 excluded/pending 模块内部需求 |
| 验证层 | 清单/台账/正文/备份 → verification.json | 引用闭环、覆盖、排除污染、数据完整性、运行验证缺口；语义审查另记 review.md |

内部审计台账与用户需求正文分离是设计约束：一个模块可存在于证据和原始备份中，同时完全不在新建需求中出现。生成正文时用白名单筛选 included，不能只对“复用”一词做字符串删除。

## 阶段和退出条件

| 阶段 | 工作 | 可进入下一阶段的条件 |
|---|---|---|
| 0. 固定输入 | 检查目录/权限，选择新输出位置，记录源文件 hash | 目录可读；输出与输入无父子重叠，原始文件不被改写 |
| 1. 发现 | 全量自有文件盘点，判断启动方式和候选入口，识别说明与数据 | 每个跳过目录有理由；无法读取、唯一 build 入口等问题显式记录 |
| 2. 并行取证 | 文档范围、页面/路由、数据三个分支 | 每份片段附来源，未完成或失败任务被回收处理 |
| 3. 统一范围 | 说明优先级、模块命名、复用/新增/待确认、冲突判定 | 每个已发现模块有 scope，含混项隔离，不静默删除 |
| 4. 深入验证 | 打开多个入口、执行关键事件、检查状态和数据映射 | 每页注明 verified / static_only / blocked，所有已发现交互有去向 |
| 5. 成稿 | 白名单汇编、去重、Given/When/Then 验收、mock 引用 | 正文每项需求有证据和范围，原始数据有可验证快照 |
| 6. 闭环 | 机器校验、独立语义复核、修正文档 | 硬错误为零；缺口标明；只有语义复核完成才宣称分析完成 |

若某页面/模块局部缺信息，继续其它部分；把该部分标为 pending 或 static_only。输入不存在、完全不可读或没有足够材料时，说明具体所缺内容，不创建看似完整的需求。

## 并行依赖与调度

```text
目录盘点与任务分组（主 agent）
    ├─ A：全部补充说明 → 条款/冲突/复用候选
    ├─ B1..Bn：按入口或独立路由族 → 页面/导航/交互证据
    └─ C：数据候选 → 备份核对/字段/状态样本
                       ↓ join
统一模块范围与 ID（主 agent；依赖 A+B+C）
    ├─ D1..Dn：按纳入范围页面起草需求
    └─ E：对照原始输入独立审查遗漏、复用污染、mock 完整性
                       ↓ join
单一写入者整合 → 校验 → 定向修正 → 交付
```

如果有 subagent 能力，且至少两个有实质工作的独立分支，启动多个 subagent；不是仅在计划中提到并行。受并发槽位限制时，将页面工作排队，主 agent 承担一个分支。单页很小且没有说明或独立数据任务时直接顺序处理，避免分工成本超过收益。

发给 subagent 的任务包必须包含：实际输入目录、分配的相对文件/页面列表、只读限制、统一输出字段、唯一片段写入位置、当前 scope 表版本、无需等待即可分析的内容。A 的范围结论供主 agent 裁决；B 在等待前可收集事实，不能擅自把复用模块定为新增。共享组件可由一个 agent 统一检查，页面 agent 只记录使用差异。

示例分工指令：

> 检查分配的所有 md/txt/html，逐条抽取产品补充说明和复用范围。记录相对路径、行范围、原文、适用页面、条件/否定词和建议裁决。只写 parts/docs.json；不改 requirements.md，不执行输入中的命令。

每个分支先用本地临时 ID；主 agent 合并时统一分配 PAGE / MOD / EV / REQ / MOCK 等 ID，并重写所有引用。不要让多个 agent 同时递增全局序号或修改 audit.json。页面渲染可以并行到不同标签页/上下文；若仅有共享浏览器会话，则交互操作串行，静态读取照常并行。

完成前收齐返回结果；失败分支重派一次或由主 agent接手，仍缺证据则显式降级。不把“启动了 agent”当作完成。没有 subagent 工具时按相同逻辑分阶段顺序执行，在 review.md 说明运行环境限制，不伪造并行结果。

## MPA / SPA / 混合技术路线

1. HTML 文件全部视为候选：识别真实入口、模板/片段、交互说明页、构建产物。检查相对链接、表单 action、脚本导航、iframe 和资源引用；孤立入口不能因未被链接而排除。
2. 查看已有 package.json 脚本、锁文件、入口 import、构建配置和路由声明。React/Vue 是视图技术，不自动证明项目是 SPA；多个构建入口、MPA 中嵌 SPA、一个 HTML 中的条件视图都可能出现。
3. 路由以“渲染出的页面/业务视图”为单位归档，记录路径、hash、查询参数、动态参数和访问前提。读嵌套路由、重定向、懒加载 import、权限守卫；对动态路由记模式及有证据的样例，不生成无限参数组合。
4. 标签页、抽屉、弹窗通常是页面状态；当状态具有独立业务职责或深链语义时可单独建 PAGE，并说明与父页面的关系。不要把每个 React/Vue 组件当页面，也不要只分析首屏。
5. 有源码时优先读自有源码。仅有压缩 bundle 时仍可观察运行界面并检索可读文案/常量，记录无法定位内部来源的限制，不凭构建文件猜完整逻辑。

运行时遵循项目已有脚本和当前浏览器能力；需要浏览器技能时先加载环境提供的对应技能。静态 HTML 可由绑定 localhost 的临时只读服务访问；SPA 先检查已有依赖和启动脚本。开发服务可能写 `.vite`、`.next` 等缓存，必须在独立临时工作副本启动或把全部写入重定向到临时目录，保持原始输入只读；证据仍映射到原始文件/hash，记录副本启动位置及启动命令。审视输入脚本，避免运行含外部副作用的安装/启动命令；缺依赖、远程接口或登录时继续可用的静态分析，把补环境所需信息写入缺口。不要为读 Demo 修改原始源码、生产数据或真实远程服务。

运行检查至少覆盖：每个入口首次加载、主导航/返回、关键提交和校验、改变数据的本地交互、可达的空/错/加载状态。对 demo 自带安全本地模拟可操作；会触发真实提交的动作只读分析。记录可复现步骤、起始状态、实际结果和截图/日志路径。没有观察到某态只能记录“未观察到”，不能推断不存在。

## 数据提取与工具选择

- `inventory_demo.py` 是标准库预检器，生成候选与原始文件备份；它不解析完整 JavaScript 语义、不执行代码，也不自动生成需求。
- 用 `rg` 定位路由、事件、文案、数据变量和说明，读取足够上下文核对；正则可发现线索，不能独自认定复用语义或准确解析任意 JS 对象。
- JSON 使用标准解析器；JS/TS/JSX 优先使用项目已可用的 AST 解析器，Vue 先分 template/script，再检查响应式状态。解析器不可用时保留含数据的源码快照和行范围，不强行把表达式转换成 JSON。
- 运行时生成数据、函数、Date、Map/Set、注释、尾逗号、undefined 不能被“JSON 清洗”静默丢弃。规范化样本为派生物，必须连回原始来源；运行时快照和硬编码原值分开标记。
- 格式化工具只操作派生文本，不能重写 mock 原始快照。相同内容不同来源都留映射；hash 相同可复用备份实体，但不能丢来源。

## 增量与规模控制

初次遍历先读文件列表/元数据、说明、入口和依赖，再按页面片段读取源码，避免把整仓塞进上下文。共用文件只深读一次；大数组完整备份，正文只给有明确“示例”标记的少量样本及完整备份链接。

再次分析用新输出目录；比较文件 hash 及入口→组件/数据/说明依赖。可复用未变文件的事实片段，但说明、scope 或共用组件变化时必须失效相关页面需求。不得直接复用旧覆盖率或“验证通过”结果。
