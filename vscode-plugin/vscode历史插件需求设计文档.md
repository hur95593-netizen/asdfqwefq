# VSCode 本地文件历史记录插件（windows） - 需求设计文档

## 一、WebStorm 本地历史记录功能深度分析

### 1.1 核心定位
WebStorm 的 **Local History（本地历史记录）** 是一个独立于版本控制系统（Git/SVN 等）的**个人本地版本控制系统**。它自动跟踪项目中所有文件的变更，记录每一次有意义的修改状态，允许开发者随时回溯、对比和恢复任意历史版本，即使项目没有启用任何版本控制工具。

### 1.2 核心功能特性

#### 自动记录机制
- **触发时机**：编辑代码、保存文件、运行测试、部署应用、执行版本控制操作、关闭文件/项目、退出 IDE 等事件都会自动触发快照记录
- **外部变更感知**：不仅记录 IDE 内部的修改，也能感知外部工具对文件的修改
- **智能去重**：连续快速的小修改会合并为一个历史节点，避免产生过多细碎版本
- **自动标签**：特定事件（测试运行、部署、提交等）会自动打上对应标签，便于识别

#### 历史浏览界面
- **双栏布局**：左侧为时间轴修订列表，右侧为差异对比视图
- **时间戳排序**：所有修订按时间倒序排列，精确到秒
- **标签支持**：支持手动为重要修订添加自定义标签（Label），便于快速定位关键节点
- **搜索功能**：支持按标签名或文件内容搜索历史修订
- **Recent Changes 视图**：全局视角查看所有最近变更的文件列表

#### 差异对比能力
- **并排 diff 视图**：左右分栏显示历史版本与当前版本的差异
- **高亮标记**：新增、删除、修改的行以不同颜色高亮显示
- **行内差异**：精确到字符级别的修改高亮
- **多版本对比**：可选择任意两个历史版本进行对比

#### 恢复操作
- **全文件回滚**：一键将整个文件恢复到某个历史版本状态
- **片段级恢复**：在 diff 视图中选择特定代码片段，单独恢复这部分内容
- **还原已删文件**：可以恢复已经被删除的文件及其历史
- **意外重启恢复**：IDE 或电脑意外重启后，历史记录仍然保留

#### 存储与生命周期
- **本地存储**：所有历史数据存储在本地磁盘，不依赖任何远程服务
- **保留期限**：有默认的保留期限和最大存储空间限制，超过后自动清理旧版本
- **注意事项**：升级 IDE 版本时本地历史会被清除，不能替代正式版本控制系统

### 1.3 交互入口
- 编辑器右键菜单 → Local History → Show History
- 主菜单 → File → Local History → Show History
- 双击 Shift 全局搜索 → 输入 "Local History"
- 项目视图文件右键 → Local History
- 快捷键：`Alt + Shift + C`（Recent Changes）

## 二、现有 VSCode 插件的痛点分析

### 2.1 市场现有方案对比

| 插件名称 | 核心问题 | 用户体验缺陷 |
|---------|---------|-------------|
| Local History (xpo.local-history) | 仅保存 diff 增量，恢复逻辑复杂；SSH 环境下功能异常 | UI 简陋，交互不直观；笔记本文件不支持 |
| Visual Code Time Machine | 整文件快照存储，磁盘占用大；仅支持工作区内文件 | 时间轴跳转后易出现空列表；操作笨重 |
| backtrail | 重命名识别不准确；外部快速保存可能丢失版本 | 无独立 diff 查看器，集成度低 |
| Local History Files | 功能简单，仅支持保存时快照 | 无标签、无搜索、无片段级恢复 |
| Return Back | 仅模拟 undo/redo 栈，不是真正的文件历史 | 粒度太细，重启后历史有限 |

### 2.2 共性核心痛点
1. **触发机制单一**：大多仅在文件保存时触发，缺少编辑停顿、外部变更等多维度触发
2. **UI 交互简陋**：没有类似 WebStorm 的专业双栏 diff + 时间轴布局，操作路径深
3. **恢复粒度粗**：大多只能整文件回滚，缺少片段级选择性恢复
4. **缺少标签系统**：无法标记重要节点，历史多了之后难以查找
5. **存储策略失衡**：要么全量快照占空间，要么增量 diff 恢复慢且易出错
6. **搜索能力弱**：缺少按内容、按标签搜索历史的能力
7. **已删文件恢复差**：多数插件无法很好地处理已删除文件的历史追溯

## 三、插件总体设计目标

### 3.1 核心目标
复刻 WebStorm Local History 的核心体验，打造 VSCode 平台上**最接近 WebStorm 使用感受**的本地文件历史记录插件。

### 3.2 设计原则
- **零依赖**：不依赖 Git 或任何版本控制系统，开箱即用
- **非侵入**：历史数据独立存储，不污染用户项目目录（默认放入 .gitignore）
- **高性能**：低内存占用、低磁盘 IO，后台静默运行
- **可配置**：存储策略、保留期限、触发规则全部可配置
- **原生感**：深度集成 VSCode UI 体系，使用原生 diff 视图，风格统一

### 3.3 技术栈建议
- **开发语言**：TypeScript
- **存储方案**：文件系统 + JSON 元数据索引 + 内容去重存储
- **Diff 引擎**：VSCode 内置 Diff API + `diff` 库辅助计算
- **UI 框架**：VSCode Webview API（自定义历史面板）
- **文件监听**：VSCode `workspace.onDidSaveTextDocument` + `fs.watch` 外部变更监听

## 四、详细功能需求

### 4.1 自动快照系统

#### 4.1.1 触发条件
- **保存触发**：文件保存时（`onDidSaveTextDocument`）立即创建快照
- **编辑停顿触发**：用户停止输入 3 秒后自动创建快照（可配置时长）
- **文件关闭触发**：关闭编辑器标签页时创建快照
- **外部变更触发**：监听文件系统变化，捕获外部工具的修改
- **文件删除触发**：文件被删除前自动保存最后一版快照
- **手动触发**：支持命令/快捷键手动为当前文件创建带标签的快照

#### 4.1.2 智能合并策略
- **防抖合并**：5 秒内连续保存/修改合并为一个版本
- **空变更过滤**：文件内容无实际变化时不创建新版本
- **大文件阈值**：超过指定大小（默认 1MB）的文件降低快照频率

### 4.2 历史记录面板

#### 4.2.1 面板布局（WebView）

┌─────────────────────────────────────────────────────────┐
│ 🔍 搜索框  [标签筛选▼]  [时间筛选▼]  [⚙ 设置]          │
├───────────────────┬─────────────────────────────────────┤
│                   │                                     │
│  时间轴列表       │       Diff 对比视图                  │
│  (左侧)           │       (右侧，复用 VSCode 原生 diff)  │
│                   │                                     │
│  [时间戳]         │  < 历史版本  |  当前版本 >           │
│  [标签]           │                                     │
│  [变更摘要]       │                                     │
│                   │                                     │
└───────────────────┴─────────────────────────────────────┘


#### 4.2.2 时间轴列表（左侧）
- 按时间倒序显示当前文件的所有历史修订
- 每条记录显示：时间戳、标签（如有）、变更行数统计（+/-）
- 支持单击选中，右侧实时显示对应 diff
- 支持右键菜单：还原此版本、添加标签、删除此版本、导出此版本
- 支持多选两个版本进行对比

#### 4.2.3 Diff 对比视图（右侧）
- 默认对比：选中的历史版本 ↔ 文件当前版本
- 支持切换对比方向
- 支持行内差异高亮显示
- 支持片段级恢复：点击行首箭头可将单行/单块代码恢复到当前版本
- 支持完整文件还原按钮

#### 4.2.4 搜索与筛选
- **内容搜索**：输入关键词，过滤出包含该内容的历史版本
- **标签筛选**：按标签名筛选修订记录
- **时间筛选**：按今天、昨天、本周、本月等时间范围筛选

### 4.3 标签系统
- **手动打标签**：为任意历史版本添加自定义文字标签
- **自动标签**：
  - 文件创建时自动标记 "Created"
  - 文件删除前自动标记 "Deleted"
  - 手动快照时提示输入标签
- **标签管理**：编辑、删除标签，标签颜色区分

### 4.4 恢复功能

#### 4.4.1 全文件恢复
- 右键时间轴条目 → "还原到此版本"
- 恢复前自动为当前状态创建一个备份快照（防误操作）
- 支持"还原所选及之后的所有更改"（回滚模式）

#### 4.4.2 片段级恢复
- 在 diff 视图中，每个变更块旁显示恢复按钮
- 点击后仅将该段代码从历史版本复制到当前文件
- 支持选中多行后批量恢复

#### 4.4.3 已删除文件恢复
- 在侧边栏"已删除文件"分类中查看所有被删文件的历史
- 选中后可预览内容，一键恢复文件到指定位置
- 恢复时保留完整历史记录链

### 4.5 全局 Recent Changes 视图
- 独立侧边栏面板，展示整个工作区最近的所有文件变更
- 按时间分组显示：今天、昨天、本周
- 每条记录显示：文件名、变更时间、变更类型（修改/创建/删除）
- 点击文件直接打开对应历史面板
- 支持一键回滚某个时间点的所有变更

### 4.6 存储管理

#### 4.6.1 存储结构

工作区根目录 /
├── .local-history/          # 历史存储目录（默认自动加入 .gitignore）
│   ├── blobs/               # 文件内容 blob 存储（按内容 hash 去重）
│   │   ├── a1b2c3d4...
│   │   └── e5f6a7b8...
│   ├── index/
│   │   └── files.json       # 文件路径与 blob 的映射索引
│   └── meta/
│       └── [file-hash].json # 单个文件的时间轴元数据
└── [用户项目文件...]

#### 4.6.2 存储策略配置
| 配置项 | 默认值 | 说明 |
|-------|-------|------|
| `maxVersionsPerFile` | 100 | 单个文件最多保留版本数 |
| `maxAgeDays` | 30 | 历史记录最大保留天数 |
| `maxTotalSizeMB` | 500 | 历史存储总大小上限 |
| `largeFileThresholdKB` | 1024 | 大文件阈值，超过后降低快照频率 |
| `debounceSeconds` | 3 | 编辑停顿触发秒数 |

#### 4.6.3 自动清理
- 超过保留期限的版本自动清除
- 超过最大数量时淘汰最旧版本
- 超过总大小限制时按时间顺序清理
- 清理时 blob 内容引用计数为 0 才真正删除

### 4.7 集成与入口

#### 4.7.1 命令面板（Ctrl+Shift+P）
- `Local History: Show History` - 显示当前文件历史
- `Local History: Show Recent Changes` - 显示最近变更
- `Local History: Take Snapshot` - 手动创建快照
- `Local History: Add Label` - 为当前版本添加标签
- `Local History: Clear History` - 清除当前文件历史
- `Local History: Purge All History` - 清除全部历史

#### 4.7.2 右键菜单
- 编辑器内右键 → Local History → Show History
- 资源管理器文件右键 → Local History → Show History
- 资源管理器文件夹右键 → Local History → Show Recent Changes

#### 4.7.3 侧边栏视图
- 活动栏新增 "Local History" 图标
- 包含两个视图：File History（当前文件）、Recent Changes（全局）

#### 4.7.4 快捷键
- `Ctrl+Shift+H`：显示当前文件历史
- `Ctrl+Alt+Shift+H`：显示最近变更
- 可自定义

### 4.8 排除规则
- 支持 glob 模式配置忽略文件/目录
- 默认排除：`node_modules/**`、`dist/**`、`build/**`、`.git/**`、`*.log`、`*.tmp`
- 支持工作区级和全局级配置

## 五、非功能需求

### 5.1 性能要求
- 快照创建延迟 < 100ms（后台异步）
- 打开历史面板首屏加载 < 500ms
- 内存占用常态 < 50MB
- 不影响编辑器输入流畅度（打字无卡顿）

### 5.2 可靠性
- 异常退出后历史数据不丢失
- 写入操作原子化，防止文件损坏
- 自动检测并修复损坏的索引文件

### 5.3 兼容性
- 支持 VSCode 1.80+
- 支持 Windows / macOS / Linux
- 支持多工作区（Multi-root Workspace）
- 支持远程开发（SSH / WSL / Dev Container）

### 5.4 安全性
- 所有数据仅存储在本地，不上传任何服务器
- 存储目录默认加入 .gitignore，避免提交到仓库
- 支持加密存储选项（可选）

## 七、AI Agent 开发指导清单

### 7.1 项目初始化
1. 使用 `yo code` 生成 VSCode 扩展脚手架（TypeScript）
2. 配置 package.json：activationEvents、contributes（commands、menus、views）
3. 搭建基础目录结构：`src/core`、`src/ui`、`src/storage`、`src/utils`

### 7.2 核心模块开发顺序
1. **存储模块** → 实现 blob 存储 + 元数据索引 + 读写 API
2. **监听模块** → 实现文件保存/修改/删除事件监听与快照创建
3. **Diff 模块** → 封装 VSCode 原生 diff API，实现版本对比
4. **Webview 面板** → 实现历史记录双栏界面
5. **命令与菜单** → 注册所有命令、右键菜单、侧边栏视图
6. **恢复逻辑** → 实现全文件恢复 + 片段恢复
7. **配置系统** → 读取设置、排除规则、存储策略
8. **清理机制** → 实现自动清理与过期淘汰

### 7.3 关键技术点提示
- 使用 `vscode.workspace.fs` 进行文件操作，确保跨平台兼容
- 使用 `createTerminalDiffEditor` 或 `vscode.diff` 命令调用原生 diff
- Webview 与扩展通信使用 `postMessage` 机制
- 大文件使用内容哈希去重，节省存储空间
- 所有磁盘 IO 使用异步 API，避免阻塞主线程

### 7.4 测试要点
- 多文件连续保存测试
- 大文件性能测试
- 异常退出数据完整性测试
- 删除文件后恢复测试
- 远程 SSH 环境兼容性测试
- .gitignore 自动配置测试
